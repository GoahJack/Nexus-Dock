# 灵动岛靠近展开与图钉

日期：2026-11-14。用户在手动折叠方案基础上要求「鼠标靠近自动展开，点击按钮保持展开」。本文件替代此前手动折叠说明，并包含连续形变与自动折叠卡住修复。基于 v1.9.0，无新增依赖，保留 Electron / React 与原生时钟架构。

## 本次修正

用户反馈「直接放大突兀」「音乐和单词动态折叠未生效」。分别查到两个原因：只读检查本机配置时两个模式开关均为 false；另外旧构建在 Windows 原生拖动区域漏发 DOM pointerleave/pointerup 时，hover/press 状态会一直保留，确实能使已开启的模式不再收起。

前者属于开关状态，设置页新增「动态折叠：未启用 / 已开启 / 已固定展开」提示；保持用户配置，不擅自打开。后者已通过修复前回归重现：`verification/motion-island/baseline/report.json` 中音乐、单词两项失败；修复后的同一用例通过，见最新 report.json。

原生靠近结果为 false 时清除过期 hover/press，真正的 pointer capture、输入和键盘保护保留。进入/按下后再做一次 200ms 的原生核验，覆盖整个悬停落在两次 100ms 检测之间、没有状态变化事件的情况；读取结果不会覆盖更新的事件。该核验不是常驻轮询。

## 当前行为

**Dock 始终展开，不参与靠近检测。** 音乐、单词、时钟的灵动岛开关仍位于设置；原「收起为胶囊」改为「灵动岛：靠近时展开」。原配置关闭时继续始终展开；原配置开启时升级为自动靠近展开。首次使用默认不开启，避免擅自改变用户布局。

| 条件 | 显示行为 |
| --- | --- |
| 模式关闭 | 始终展开，图钉不显示 |
| 模式开启、指针远离 | 胶囊 |
| 指针距胶囊矩形不超过 24 DIP | 立即展开，不需要进入窗口 |
| 已展开时距当前窗口与原胶囊区域超过 40 DIP | 等待 900ms 后收起 |
| 指针返回、键盘焦点、输入框编辑、按住指针 | 保持展开，取消收起计时 |
| 图钉「保持展开」开启 | 始终展开，跨重启保留 |
| 再次点击图钉 | 恢复自动行为；鼠标仍在窗口内时继续展开，移开后收起 |

检测使用屏幕逻辑像素（DIP），24/40 两档边界防止来回抖动。展开引起窗口大小和位置变化时保留原胶囊命中区，避免指针被新边界甩出后反复开合；窗口平移则清除旧命中区。真实尺寸形变期间额外检查最近一次检测到的边界，确保收起中的边缘不会在两次检测之间躲开指针；尺寸稳定后不保留该额外区域。

设置入口：

- 音乐 / 时钟：窗口 → 内置窗口 → 对应窗口。
- 英语单词：窗口 → 附加窗口 → 英语单词学习。
- 每处包含「灵动岛：靠近时展开」与「保持展开」。后者与窗口图钉双向同步；模式关闭时禁用该设置，但保留原图钉偏好。

「保持展开」独立于「锁定位置」。锁定后图钉依然可点。关闭/隐藏窗口不等于折叠。时钟胶囊隐藏秒和日期，展开恢复原显示偏好。单词完整内容保持挂载，折叠不丢当前词、视图、搜索框与编辑草稿；胶囊状态不触发学习评分快捷键，键盘焦点可展开并转移到可见图钉。

## 技术取舍与数据

仅监听 pointerenter 最简单，但无法在指针进入窗口之前展开；扩大透明窗口命中区会影响桌面点击。本实现使用主进程共享的屏幕距离检测，避免扩大透明点击区域，开发与验证成本略高，但三个窗口复用同一套逻辑。

- 复用 `music.collapsed`、`clock.collapsed`、`extraWindows[].collapsed` 作为模式开关，保留旧配置兼容性。
- 新增各自的 `pinned: boolean`，默认 false；显式 true/false 独立持久化。schemaVersion 继续为 11，沿用缺失字段补齐。
- 靠近、焦点和交互保护都是临时状态，不通过 settings.update 落盘。
- 新增 `island:proximityGet`（只读取 IPC 发送者自身窗口）与 `island:proximityChanged`（布尔事件）。
- 主进程 `islandProximity.ts` 注册音乐、时钟、附加窗口，不注册 Dock/设置。
- 共享 `IslandExpansion` 处理开启/固定/靠近/交互/900ms 计时；DOM 适配器负责指针与焦点，React hook 和原生时钟共用同一适配器。
- 窗口关闭、应用退出与组件卸载时清理监听、计时器和动画。初始查询不会覆盖后到的靠近事件。

## 视觉与动效

沿用石墨色与冰蓝色视觉。图钉采用一致图标、悬停反馈和键盘焦点环；按下状态使用强调色，并设置 aria-pressed / 操作名称。

外壳的真实宽、高和圆角连续变化，基准 320ms，曲线 cubic-bezier(.22,.85,.25,1)，时长随动效强度缩放。文字保持自然字号，不对整卡 transform/scale。新内容在展开后延迟 60ms、收起后延迟 30ms 淡入，淡入基准 180ms。快速反向操作从当前中间尺寸继续，结束后清除临时宽高、裁切和圆角，恢复自然布局。

**有意调整旧实现约束**：此前只上报最终尺寸、对文字淡入，导致外壳跳变。本次在约 320ms 的形变期间按 ResizeObserver 同步原生窗口尺寸，复用现有 IPC。代价是交互期间短暂的原生 resize；动画结束后不再产生尺寸更新。尺寸 hook 不为每个中间值重渲染整张音乐卡片；布局守卫使用版本号，旧的 80ms 定时器不能提前解除新一帧的程序化移动保护，避免动画被保存成用户拖动位置。

不采用快照缩放来伪装形变，避免文字随卡片放大或缩小。系统/用户减少动效时立即到目标状态；动画中开启减少动效、窗口隐藏或组件卸载也会取消动画并还原布局。

音乐播放器保持挂载；胶囊模式停止进度动画帧，展开从时间锚点补齐。时钟胶囊按分钟显示，展开恢复秒/日期。单词错误提示继续可见。

## 性能

主进程只有一个 100ms 检测器，每次仅获取一次屏幕指针位置；仅对可见、开启模式且未固定的窗口比较边界。状态变化时才发 IPC，边界内移动不会持续触发 React 更新。

所有相关窗口被隐藏、固定或关闭模式后清除检测计时器。保留之前的运行态渲染去重、进程采集并发保护、音乐进度最高 30fps 与轻量投影。未做统一硬件/负载的 CPU、GPU、内存前后基准，不宣称改善百分比。

## 后续窗口接入

附加窗口注册表与默认配置自动补齐模式和图钉字段；其渲染页仍需调用 useIsland 或 bindIsland，并放置图钉控件，以响应自动展开。不要为新窗口单独增加指针轮询，也不要把瞬时展开状态写入 settings.json。

## 使用与排查

1. 退出正在运行的旧版，再启动 motion 便携版；否则单实例机制仍会激活旧窗口。
2. 设置 → 窗口 → 对应音乐/单词窗口，打开「灵动岛：靠近时展开」。开关关闭时始终展开，这是正常行为。
3. 「保持展开」关闭，移出窗口及原胶囊 40 DIP 范围，等待 900ms 后开始约 320ms 收起。
4. 正在输入、使用键盘控件或捕获指针拖动时会保持展开；完成操作/移走焦点后恢复。

实际用户配置没有被本次自动化更改。运行验证使用隔离应用与模拟原生指针；用户设备的真实鼠标手感仍需体验。

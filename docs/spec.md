# SPEC — Nexus 风格桌面美化工具（Dock + 音乐显示）

> 文档版本：v0.1 主体 + §7 v1.0 精细化交互增补（2026-10-30 已实现并验收，见 `docs/verification.md` §v1.0）
> 状态：已确认（用户 2026-10-29 决策：Electron + React + TS；SMTC + 本地播放器；MVP 范围；先交付开发态可运行版本；2026-10-30 决策：Apple Dock 物理回弹风格、按压 + 涟漪 + 启动反馈、新增「外观与动效」设置页）

## 1. 背景与目标

桌面美化软件 Nexus 的核心体验是：一条悬浮在桌面上的应用栏（Dock），图标会随鼠标悬停放大，并在旁边显示当前播放的音乐信息。本项目要复刻这一体验并做成可二次开发的工程。

**产品目标（v0.1）**：一条**位置可以调整**的 Dock + 一个**音乐显示**小组件，全部参数可在设置面板中调整、重启后保持。

**非目标（v0.1 不做）**：多显示器独立配置、开机自启、系统托盘常驻、皮肤包市场、图标倒影/3D 透视、打包安装包（打包在验收通过后单独进行）。

## 2. 名词约定

| 名词 | 含义 |
|---|---|
| Dock | 悬浮应用栏窗口，内含一组图标 |
| 停靠边（edge） | Dock 贴靠的屏幕边：bottom / top / left / right |
| 沿边位置（alongPercent） | Dock 在停靠边上的位置百分比，0 = 左端/上端，100 = 右端/下端 |
| 音乐卡片 | 独立悬浮窗口，显示封面 / 标题 / 歌手 / 进度 / 播放控制 |
| SMTC | Windows 系统媒体传输控件（GlobalSystemMediaTransportControlsSession），可读到任意播放器的曲目信息 |
| 本地播放器 | 内置的音频播放能力，直接播放本地音频文件 |

## 3. 用户故事与验收标准

### US-1 位置可调的 Dock（P0）

**作为** 用户，**我希望** 把 Dock 放在屏幕任意一边、任意位置，**以便** 匹配我的桌面布局和使用习惯。

验收标准：
1. **AC-1.1** 首次启动，Dock 出现在屏幕底部居中，带圆角、半透明玻璃质感，悬浮在窗口之上、不进入任务栏。
2. **AC-1.2** 用鼠标按住 Dock 上的拖拽手柄拖动，Dock 可自由移动；松手后自动吸附到最近的屏幕边（上/下/左/右），并与屏幕边保持 12px 间距。
3. **AC-1.3** 吸附后沿边位置保留（拖到屏幕右下角附近就贴在右下侧，不会跳回居中）。
4. **AC-1.4** 设置面板中可把停靠边切换为 上/下/左/右，Dock 立即重新排列（水平条 ↔ 垂直条），图标方向随之正确。
5. **AC-1.5** 设置面板中可用滑块微调沿边位置（0–100%），Dock 实时移动。
6. **AC-1.6** 所有位置参数（edge / alongPercent / 尺寸 / 间距）持久化到 `%APPDATA%/nexus-dock/settings.json`，重启应用后完全还原。
7. **AC-1.7** Dock 上有可识别的拖拽手柄（grip），鼠标悬停时提示“拖动以移动 Dock”。

### US-2 图标交互与 Nexus 观感（P0）

**作为** 用户，**我希望** 用 Dock 启动应用，且鼠标经过时图标放大，**以便** 得到 Nexus 那样的流畅手感。

验收标准：
1. **AC-2.1** Dock 显示一组应用图标（内置默认 6 个：文件资源管理器、记事本、计算器、画图、设置、浏览器或等价系统应用），图标清晰无白边。
2. **AC-2.2** 鼠标悬停图标时，该图标放大到可配置倍率（默认 1.30），相邻图标按距离递减放大（±1 为 1.18、±2 为 1.06），并向上浮起 8px；移开 180ms 内平滑复位，无布局抖动。
3. **AC-2.3** 单击图标启动对应应用；Dock 窗口不抢焦点时点击只有一次响应，不出现“点两下才生效”。
4. **AC-2.4** 右键图标弹出原生上下文菜单：打开 / 在资源管理器中显示 / 从 Dock 移除 / Dock 设置。
5. **AC-2.5** 鼠标按住图标横向（或竖向）拖动可调整图标顺序，松手后顺序持久化。
6. **AC-2.6** 音量/亮度等占位图标不出现；每个图标下方有 4px 运行状态指示点（进程在运行时高亮）。

### US-3 音乐显示（P0）

**作为** 用户，**我希望** 在桌面上看到当前正在播放的音乐，**以便** 不用切窗口就能知道在放什么、并快速控制。

验收标准：
1. **AC-3.1** 音乐卡片显示封面、标题、歌手、进度条与时间（已播/总长）。
2. **AC-3.2** 数据源为 Windows SMTC：当系统里有任意播放器（Spotify / 网易云 / QQ 音乐 / Edge 浏览器等）在放歌时，卡片自动显示其曲目，切歌自动刷新。
3. **AC-3.3** 卡片上的 上一首 / 播放暂停 / 下一首 按钮能真正控制当前系统播放器；播放状态图标随之变化。
4. **AC-3.4** 没有任何播放器在播放时，卡片显示“未在播放”的空状态，不崩溃、不残留旧封面。
5. **AC-3.5** 音乐卡片可独立显示/隐藏（默认显示），位置可跟随 Dock，也可自由拖动吸附到屏幕任意一边，参数持久化。
6. **AC-3.6** 内置本地播放器：可从设置面板选择本地音频文件（mp3/wav/flac/m4a/ogg），音乐卡片切换为本地曲目并支持播放/暂停/上一首/下一首/拖动进度。
7. **AC-3.7** 卡片宽度、进度样式（条形/环形）可在设置面板调整并实时生效（卡片高度随内容自适应，避免比例失真）。

### US-4 设置面板（P0）

**作为** 用户，**我希望** 在一个面板里调整所有外观与行为参数，**以便** 把桌面临调到我喜欢的样子。

验收标准：
1. **AC-4.1** 右键 Dock →「Dock 设置」可打开设置窗口；窗口可拖动、可关闭、不进入任务栏、始终置顶。
2. **AC-4.2** 设置分三组：Dock（停靠边、沿边位置、图标尺寸、悬停放大、图标间距、运行指示点、悬浮置顶、亚克力/玻璃）、音乐（显示、宽高、进度样式、跟随 Dock 或自由位置）、应用（列表、添加 exe、移除、排序、恢复默认）。
3. **AC-4.3** 任意参数修改后立即生效并写入磁盘（防抖 ≤ 300ms），无需点“保存”。
4. **AC-4.4** 面板上有「恢复默认设置」按钮，二次确认后全部参数回到默认值并即时生效。
5. **AC-4.5** 面板底部显示版本号与进程信息，帮助定位问题。

### US-5 工程质量与可验证性（P0）

1. **AC-5.1** `npm install && npm run dev` 在 Windows 10/11 + Node 20+ 上一条命令启动，控制台无红色报错。
2. **AC-5.2** `npm run build` 成功产出 `out/`，`npm run typecheck` 零错误。
3. **AC-5.3** 主进程 / 预加载 / 渲染进程严格分离：`contextIsolation: true`、`nodeIntegration: false`，渲染层只能通过 `window.nexus` 白名单 API 与主进程通信。
4. **AC-5.4** 所有持久化文件只在 `app.getPath('userData')` 下读写；SMTC 桥进程异常退出会自动重启（≤3 秒），不影响 Dock 使用。
5. **AC-5.5** 提供 `docs/verification.md`：逐条 AC 的验收方式与实测结果（含截图/日志证据）。

## 4. 约束

- 目标平台：Windows 10 1809+ / Windows 11（当前开发机 Windows 11 build 26200）。
- 技术栈：Electron（主进程 TS）+ React 19 + TypeScript + Vite（electron-vite 构建）。
- 不引入需要本地编译的原生模块（node-gyp），避免 Node 24 环境编译失败；SMTC 通过 Windows PowerShell 的 WinRT 接口访问（已实测可用）。
- 安装依赖走 npmmirror 镜像；npm 缓存必须位于工作区内（沙箱限制）。
- 中文界面（zh-CN）。
- **窗口行为必须遵守 `docs/window-conventions.md`**（v1.2 起强制）：今后所有悬浮窗口必须提供「自动吸附屏幕边缘」开关（默认开）、位置记忆、位置锁定、显示开关等能力，并按该准则的接入清单与验收契约实现。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 透明/亚克力窗口在个别显卡驱动下显示异常 | Dock 变成纯黑块 | 提供“玻璃质感”开关，可切回纯色半透明；截图验收 |
| SMTC 在无播放器时返回空会话 | 音乐卡片空白 | 空状态 UI + 桥进程容错 |
| 无边框窗口点击穿透/焦点问题 | 首次点击无响应 | 启动时 `showInactive()`，Dock 窗口可聚焦但不抢焦点 |
| 图标取不到（UWP 应用） | 空图标 | 回退到字母占位图标 |
| npm/Electron 二进制下载慢 | 卡住进度 | 镜像源 + 后台安装 + 失败重试 |

## 6. v0.2 变更（2026-10-29 用户反馈驱动）

新增 / 调整的需求，优先级同上：

### US-6 Dock 行为增强
1. **AC-6.1 自由定位（默认）**：拖动 Dock 松手后停在原地，不再强制吸附屏幕边缘；设置面板提供「吸附到屏幕边缘」开关（默认关，开启后恢复吸附最近边的旧行为）。
2. **AC-6.2 背景完全透明（默认）**：Dock 底条默认完全透明，只显示图标；设置面板「背景不透明度」0–100% 可调（0 = 完全透明，>0 显示玻璃底条）。
3. **AC-6.3 仅桌面显示**：前台窗口最大化或全屏时自动隐藏 Dock；回到桌面（或 Dock 自身获得焦点）后自动恢复。设置面板提供「仅在桌面显示」开关（默认开）。
4. **AC-6.4 Dock 音乐开关**：Dock 末端常驻音符按钮，点击切换音乐卡片显示/隐藏；卡片可见时按钮高亮。

### US-7 音乐体验修正
1. **AC-7.1 时间准确性**：进度时间以 SMTC 的 `Position + (now - LastUpdatedTime)` 推算；播放器不上报总时长时显示 `已播 / --:--`，进度条不得出现 NaN/满格等错误表现。
2. **AC-7.2 卡片关闭按钮**：音乐卡片右上角 ✕ 可隐藏卡片（与 Dock 音符按钮、设置开关共享 `music.visible`）。

### US-8 应用启动与目录修复
1. **AC-8.1 可靠启动**：应用统一通过 `shell:AppsFolder\<AppID>` 启动（覆盖 UWP/Store/桌面程序），失败时按 参数→shell.openPath→直接 spawn→cmd start 顺序回退，并把具体原因显示在 Dock 上方提示条。
2. **AC-8.2 应用目录可用**：设置 → 应用 →「从开始菜单选择」通过 `Get-StartApps` 返回本机应用（AppID 同时作为启动标识），支持搜索与添加；添加后即可在 Dock 上点击启动。
3. **AC-8.3 环境健壮性**：所有 PowerShell 子进程显式注入 TEMP/APPDATA/LOCALAPPDATA/ProgramData 环境变量；SMTC 封面目录在 TEMP 不可用时回退到系统临时目录。

## 7. v1.0 变更（2026-10-30 用户确认：精细化交互设计）

### 7.1 设计目标

在功能已可用的 v0.9 基础上做「手感层」升级：建立一套可配置、可降级、可验收的统一动效语言（Apple Dock 物理回弹风格），覆盖 Dock、音乐卡片、设置面板三个窗口的所有可交互元素，并把控制权交给用户（外观与动效设置页）。

动效规范细则（令牌、时长、曲线、组件矩阵）见 **`docs/motion-spec.md`**，该文档是本轮实现的唯一视觉真源。

### 7.2 用户故事与验收标准

#### US-9 统一动效体系（P0）

**作为** 用户，**我希望** 每一次悬停、按下、点击、启动都有连贯且有物理感的反馈，**以便** 操作有确定感、界面显得精致。

1. **AC-9.1 动效令牌统一**：所有时长/曲线/幅度来自 `theme.css` + `motion.css` 的 CSS 变量，不得在组件内硬编码毫秒数；三窗口共用同一套令牌。
2. **AC-9.2 按压变形**：所有按钮/图标按下时缩小（Dock 图标 0.94、普通按钮 0.97、音乐控制 0.90），阴影同步收缩，松手以轻微过冲的 spring 曲线回弹；按下反馈发生在 `pointerdown`，不等 `click`。
3. **AC-9.3 涟漪/光晕**：Dock 图标、音乐卡片按钮、设置面板按钮与列表操作按钮点击时，以点击位置为圆心扩散一圈强调色光晕；光晕挂在独立图层，不改变布局、不遮挡图标；动画结束自动移除 DOM。
4. **AC-9.4 启动反馈**：点击 Dock 图标后 500ms 内图标朝屏幕内侧弹跳一次（Acknowledgement），并伴随光晕；启动失败时追加现有 toast 提示，不回滚弹跳。
5. **AC-9.5 悬停光效**：Dock 图标悬停时除放大/上浮外，增加强调色柔光投影；放大与光效随邻项衰减，移开 180ms 内复位。
6. **AC-9.6 运行指示点**：运行中指示点带 2.6s 呼吸动画（透明度/缩放轻微脉动）；悬停图标时指示点高亮增亮。
7. **AC-9.7 拖拽排序过渡**：Dock 图标重排使用 FLIP（先测量后动画），槽位交换 260ms spring 过渡，不再瞬移；拖拽中的图标有抬升与投影，放下后归位。
8. **AC-9.8 容器过渡**：Dock/音乐卡片/设置页出现有入场动画；Dock 新图标有错峰入场；启动失败 toast 有进出动画。
9. **AC-9.9 音乐卡片控件**：播放/暂停按钮图标形变过渡（morph 观感）；上一首/下一首点击有方向性微动；进度条 hover/drag 时轨道增高、滑块放大发光、填充发光；切歌封面交叉淡入。
10. **AC-9.10 设置面板控件**：导航项、按钮、开关、滑块、分段选择、应用列表行、窗口控制按钮具备 hover/press/focus/disabled 四态；页面切换有 220ms 淡入位移过渡；恢复默认弹层与二次确认条有进出动画。
11. **AC-9.11 可访问性与降级**：系统 `prefers-reduced-motion: reduce` 或用户开启「减少动效」时，全部动画时长收敛为 0.01ms（涟漪与呼吸不播放），布局与功能不受影响。
12. **AC-9.12 性能约束**：动效只使用 `transform` / `opacity` / `filter` / `box-shadow`（后两者限静态状态），不得触发布局抖动；拖拽排序中不产生 React 全树重渲染以外的额外布局跳动。

#### US-10 外观与动效设置（P0）

**作为** 用户，**我希望** 自己控制动效强度与音效，**以便** 匹配性能和偏好。

1. **AC-10.1** 设置面板新增「外观与动效」页（导航第 4 项，位于「应用」与「关于」之间），含：动效强度（轻快 / 标准 / 弹性）、减少动效开关、点击音效开关、效果预览区。
2. **AC-10.2** 动效强度实时生效：轻快 = 时长 ×0.72 且无过冲；标准 = ×1 轻微过冲；弹性 = 时长 ×1.28 且明显过冲。切换后立即影响所有窗口。
3. **AC-10.3** 「减少动效」开启后，所有窗口动画/过渡时长收敛至 0.01ms；关闭后恢复。
4. **AC-10.4** 点击音效默认关闭；开启后点击可交互元素播放内置合成短音（不依赖外部音频文件，可随时关闭）。
5. **AC-10.5** 全部外观参数持久化到 `settings.json`，schemaVersion 3 → 4 平滑迁移，旧配置不丢失。
6. **AC-10.6** 效果预览区可直接试听/试看当前动效强度（含按压、涟漪、音效），无需来回切换窗口。

### 7.3 非目标（v1.0 不做）

- 不引入动效库（framer-motion / react-spring），保持零新增运行时依赖。
- 不做主题皮肤市场、不做自定义强调色、不做窗口级淡入（由 OS 负责）。
- 不实现图标移除动画（React 卸载时机难以保证，列入 v1.1 候选）。
- 点击音效只做内置合成音，不提供导入自定义音效。

## 8. v1.1 变更（2026-10-30 用户确认：音乐吸附 / 开机自启 / 桌面时钟 / 位置锁定 / SDD）

> 文档版本：v1.1 增补。状态：需求已确认（用户在动手前确认四个决策点：位置锁定采用「全局总开关 + 单窗口覆盖」、时钟为「数字时钟 + 常用选项」、音乐吸附默认开启、设置面板新增「时钟」「系统」两页）。**已实现并验收**（2026-10-30）：实现与逐条 AC 证据见 `docs/verification.md` §v1.1（31/31 项通过）。

### 8.1 设计目标

在 v1.0 的四窗口体系（Dock / 音乐卡片 / 设置 / 动效令牌）基础上补齐四类「桌面常驻体验」能力，并保持与既有架构一致：**设置唯一真源 + 主进程统一窗口位置引擎 + 渲染层只读契约**。

1. **音乐窗口吸附开关**：拖动音乐卡片后的落点行为可配置（吸附最近屏幕边 / 自由摆放），默认保持 v1.0 的吸附行为。
2. **开机自启开关**：安装版可一键注册/取消 Windows 当前用户登录启动项，开发模式安全降级。
3. **桌面时钟窗口**：新增可独立显示/隐藏的数字时钟悬浮窗，支持常用外观选项与位置记忆。

## 11. v1.3.1 修复（2026-11-01 用户反馈：Dock 唤起应用要保留原窗口状态）

> 文档版本：v1.3.1 补丁。状态：**已实现并验收**（CDP + Win32 窗口状态探测 10/10 通过，见 `docs/verification.md` §v1.3.1）。

### 11.1 问题与根因

**现象**：一个已运行且处于最大化状态的应用，从 Dock 点击唤起时，窗口会先以最大化出现，随后又变成普通窗口。

**根因**：`src/main/apps.ts` 的 `Activate-Win` 在置前时**无条件**调用 `ShowWindow(hwnd, 9)`（`SW_RESTORE`）。`SW_RESTORE` 的语义是「还原窗口」，会把最大化窗口强制还原为普通窗口，因此出现「先最大化出现、随即被还原」。

## 12. v1.4.1 修复（2026-11-01 用户反馈：点击 Dock 里的 DockApp 自身图标要打开设置）

### 12.1 问题与根因

**现象**：用户把安装版 `NexusDockApp.exe` 自己加进 Dock，当作「设置入口」。点击这个 DockApp 图标时设置面板不出现——看起来「点了没反应」，实际可能只是把桌面时钟窗口置前（时钟可见时）。

**根因链条**（`src/main/apps.ts`）：

1. Dock 里的自身图标 `path` 指向本程序 exe（`%LOCALAPPDATA%\NexusDock\NexusDockApp.exe`），`aumid` 也可能存 exe 路径或 `.lnk` 快捷方式。
2. 点击后 `launchApp` 走启动链路，先进入 `launchAndFocus` 的「已有窗口优先」分支：PowerShell 用 UI Automation 枚举顶层窗口，凡「进程名 = 标称进程名」或「窗口标题命中提示词」的窗口都被当作目标应用窗口（`Test-TargetWindow`）。
3. Dock / 音乐卡片 / 设置 / 桌面时钟四个窗口的可执行文件都是 `NexusDockApp.exe`（Electron 多进程：主进程与各渲染进程同名），窗口的进程名均为 `NexusDockApp`。脚本用 `$selfTitles` 排除自身窗口，但名单只有 `NexusDockApp|Nexus Dock|Nexus Music|Nexus 设置`，**漏了桌面时钟的窗口标题 `Nexus 时钟`**。
4. 于是时钟窗口被误判为「目标应用窗口」：`Activate-Win` 只把它置前并返回 `FOUND`，**不会启动第二个实例**——「已有窗口优先」的设计就是避免重复启动。
5. 第二个实例不启动，`second-instance` 事件就不会触发，`openSettingsWindow()` 自然也不会执行。用户点 DockApp 图标 → 只有时钟窗口被置前（时钟可见时），设置面板不出现。

### 15.1 背景与设计目标

v1.8 的单词学习只有「未学 / 学习中 / 已掌握」三态标记 + 上一词/下一词翻词，**标记完就再也不会主动回来**：用户既不知道「哪些词该复习了」，也没法按认识状态浏览和整理词表。v1.9 在**不新增窗口、不新增 IPC 通道、不改设置 schema** 的前提下补齐两件事：

1. **按认识状态整理**：单词窗口新增第三个视图「单词表」（与「学习」「词库管理」并列，480 级宽），可按 5 档状态筛选（全部 / 待复习 / 未学 / 学习中 / 已掌握，带计数）、按单词/释义搜索、按 3 档排序（词库顺序 / 到期优先 / 字母 A→Z），并可在行内直接改状态或跳到该词学习。
2. **遗忘曲线复习（简化 SM-2）**：每个词记录 `dueAt / intervalDays / ease / streak / lapses`，用「不认识 / 模糊 / 认识」三档评级排下一次复习时间；卡片头部常驻「待复习 n」入口，一键只复习到期词；标记后 toast 给出下次复习间隔，记忆计划条显示当前排期。
3. **旧进度零丢失**：`wordbank-progress.json` 由 v1 自动迁移到 v2（已学词 `dueAt=lastSeenAt`，升级后立即进入待复习），用户不需要做任何操作。
4. **复用既有数据通道**：11 个 wordbank IPC 通道与主进程 `src/main/wordBank.ts` 零改动，进度文件版本由共享常量 `WORD_PROGRESS_VERSION=2` 自动写出；`settings.schemaVersion` 仍为 11（新增的 2 个学习选项由注册表 `defaultOptions` 经 `sanitizeWindowOptions` 自动补齐）。
